Every switch used to mean re-explaining the project

Coding agents keep their conversations in their own formats. Moving from one to another meant copying context by hand, or starting over: the goal, the decisions, which files changed, what was still left.

wormhole reads the session you are in and writes a real native session for the next tool, the same file its own resume command opens. Nothing to paste, and the agent sees the history as if it had been there.

How it works

Each project directory gets one thread. Every tool's session feeds it; every switch writes from it.

Import

New turns from Claude Code transcripts, Codex rollouts and opencode exports become tool-neutral events in ~/.wormhole: user and assistant text, tool calls and results, file changes.

Write

wormhole writes a native session for the target: user and assistant text verbatim, each tool call as one line (▸ Bash: npm test → ok), then a handoff brief with the goal, open tasks, files touched and git state.

Resume

It opens with the tool's own command, or in Claude Desktop or Codex Desktop with --app. Going back to a tool extends a copy of its own session, so its native tool calls survive.

Built for the way you actually switch

Small commands, safe defaults, and nothing leaves your machine.

switch · resume

One command each way

wormhole switch codex, wormhole switch claude, wormhole resume. Round trips keep each tool's own history.

hooks

Always up to date

wormhole hooks install adds a Claude Code SessionEnd hook, a Codex notify wrapper and an opencode plugin, so every turn lands in the thread.

accounts · next

Several logins, no dead ends

Use claude@work or codex@alt. When a session hits its usage limit, wormhole next moves to the next account or tool with room.

--lean

Fewer tokens on long sessions

Start the next agent from the brief alone; the full conversation waits in a file it can read when it needs it.

--summarize

A summary from the tool you leave

Ask the outgoing agent for a 10-line summary for the brief, without adding a turn to your session.

--app

Desktop apps too

Open handoffs in Codex Desktop or Claude Desktop through their own links, or stay in the terminal.

doctor

Know it works

wormhole doctor checks tools, logins, hooks, accounts and the store, with a fix for each problem.

Quickstart

Node 22 or newer. In a project where you have been working with Claude Code:

$ npm i -g @wormhole-cli/wormhole
$ wormhole hooks install      # optional: import after every turn
$ wormhole switch codex       # Codex opens with the conversation so far
$ wormhole switch claude      # back again, with what happened in Codex
$ wormhole next               # out of usage? move to the next account or tool

FAQ

Does anything leave my machine?

No. wormhole reads and writes the tools' own files locally and keeps its threads in ~/.wormhole. The only network traffic is the tools themselves when you run them.

Can it break my existing sessions?

It never edits or deletes a native session. Switching back writes a copy under a new id; the original is untouched.

What about the model's reasoning?

It is never copied across tools: Claude's signed thinking and Codex's encrypted reasoning only verify with their own provider. Text, tool calls and results carry over.

Is it the full tool output?

Tool calls cross tools as one-line summaries. Output over 4,000 characters is cut in the thread and kept whole on disk, with a pointer the next agent can read.

Which platforms?

macOS (Apple silicon and Intel), Linux and Windows, with Node 22+. The test suite runs on all three on every change.
